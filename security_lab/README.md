# Лаборатория: подбор пароля (для своего сайта)

Набор для учебного эксперимента: как машинный перебор ломает слабый пароль и что
именно превращает «3 секунды» в «92 года».

> **Область применения.** Своя машина и своя локальная сеть — `localhost`,
> `127.0.0.1`, `host.docker.internal`, `*.local`, `192.168.x.x`, `10.x.x.x`,
> `172.16–31.x.x`. Скрипт **сам отказывается** работать с публичным адресом.
> Проверка чужого логина без письменного разрешения — правонарушение
> (ст. 272 УК РФ; в ЕС/UK — Computer Misuse Act и аналоги).

## Файлы

| Файл | Что делает |
|---|---|
| `guess_password.py` | словарь + **полный перебор всех паролей**, оценка объёма и ETA |
| `target_demo.py` | учебный сайт: `/` без защиты, `/protected` с блокировкой |
| `wordlist.txt` | 150 самых частых паролей (rockyou-подобный список) |

Зависимостей нет, только Python 3.8+.

## Быстрый старт

Терминал 1 — стенд (пароль можно задать любой):

```bash
python3 target_demo.py                 # пароль sunshine
python3 target_demo.py --password k9z  # свой пароль для опыта
```

Терминал 2 — словарь:

```bash
python3 guess_password.py --url http://localhost:8000/ \
    --wordlist wordlist.txt --fail-text "Неверный пароль"
```

```
Попыток: 48   Время: 0.04 с   Скорость: 1215.6 попыток/с
ПАРОЛЬ НАЙДЕН: 'sunshine'
```

Сравните с защищённой формой:

```bash
python3 guess_password.py --url http://localhost:8000/protected \
    --wordlist wordlist.txt --fail-text "Неверный пароль"
# [429] сервер ограничивает попытки — пауза 1.0 с (подряд: 3)
# Сервер стабильно блокирует перебор — защита работает.
```

## Режим «перебрать все пароли»

Включается флагом `--charset` — это алфавит, по которому идёт перебор от
`--min-len` до `--max-len`. Словарь при этом можно оставить: сначала пойдёт он,
потом остальное (повторы автоматически отбрасываются).

Готовые алфавиты: `digits`, `lower`, `upper`, `alnum`, `alnum-big`, `full`,
`lower-ru`. Можно задать и свою строку символов, например `--charset abc12`.

Сначала посмотрите объём, ничего не отправляя:

```bash
python3 guess_password.py --url http://localhost:8000/ \
    --charset alnum --min-len 1 --max-len 8 --dry-run
```

```
Полный перебор: алфавит 36 симв. длина 1..8 → 2 901 713 047 668 вариантов
  медленный сервер с лимитом попыток (10 попыток/с): 9.2 тыс. лет
  быстрый локальный сервер без защиты (1000 попыток/с): 92.0 лет
```

А вот реальный перебор короткого пароля `k9z` (все строчные+цифры, длина 3):

```bash
python3 guess_password.py --url http://localhost:8011/ \
    --charset alnum --min-len 3 --max-len 3 --fail-text "Неверный пароль"
# Попыток: 14246   Время: 9.14 с   Скорость: 1558.7 попыток/с
# ПАРОЛЬ НАЙДЕН: 'k9z'
```

Четыре цифры — 10 000 вариантов, минута. Пять — 100 000, десять минут.
Шесть знаков `alnum` — уже 2 млрд, это сутки на быстром сервере.
Отсюда и весь практический вывод: полный перебор работает только против
коротких паролей, а против длинных работает словарь — и именно поэтому
единственная надёжная защита — лимит попыток, а не «сложность».

Полезные флаги: `--skip N` — продолжить с N-й попытки (скрипт сам подсказывает
число при остановке), `--max-attempts N` — ограничить, `--delay 0.2` — пауза.

## Откуда можно запускать (адрес)

| Адрес | Можно | Зачем |
|---|---|---|
| `http://localhost:8000/` | да | обычный запуск |
| `http://127.0.0.1:8000/` | да | то же самое |
| `http://192.168.1.5:8000/` | да | сайт на другом устройстве в вашей сети |
| `http://host.docker.internal:8000/` | да | сайт в Docker-контейнере |
| `http://mypc.local:8000/` | да | mDNS-имя в домашней сети |
| `http://example.com/login` | **нет** | чужой сервис в интернете |

Проверка «как у пользователя» делается именно через локальную сеть: поднимите
сайт на ноутбуке (`--host 0.0.0.0`), откройте его с телефона по адресу
`http://<LAN-IP ноутбука>:8000/` — увидите ровно то, что видит посетитель, — а
скрипт направьте на тот же LAN-адрес. Условия те же, что при реальной атаке:
сеть, куки, задержки.

## Как направить на свой сайт

1. Откройте форму в браузере, F12 → вкладка **Network**.
2. Введите любой пароль, нажмите «Войти».
3. У появившегося запроса посмотрите:
   - **Request Method** → флаг `--method post` или `--method get`;
   - **Payload / Form Data** → имя поля с паролем (`password`, `pass`, `pwd`) → `--field`;
   - скрытые поля (`action=login`, `csrf_token`) → `--extra K=V`.
4. Во вкладке **Elements** найдите текст ошибки (у вас это «Неверный пароль») →
   `--fail-text`.

Если форма защищена CSRF-токеном, скрипт возьмёт его сам:

```bash
python3 guess_password.py --url http://localhost:8000/ \
    --csrf-field csrf_token --wordlist wordlist.txt --fail-text "Неверный пароль"
```

Регулярку можно подогнать: `--csrf-regex 'id="token"[^>]*value="([^"]+)"'`.
Сессионные куки сохраняются между попытками — как в браузере.

## Пространство поиска и что из этого следует

| Пароль | Вариантов | При 1000 попыток/с |
|---|---|---|
| 4 цифры | 10⁴ | 10 секунд |
| 6 цифр | 10⁶ | 17 минут |
| 8 строчных букв | 26⁸ ≈ 2·10¹¹ | 6 лет |
| 8 символов всех классов | 94⁸ ≈ 6·10¹⁵ | 190 000 лет |
| «sunshine» из словаря | 1 из ~14 млн (rockyou) | секунды |

Формула: `ожидаемое число попыток ≈ N / k`, где N — размер пространства или
словаря, `k` — сколько попыток сервер физически позволяет в секунду. Уменьшив `k`
до 1, вы умножаете время атаки на тысячу, не меняя ни одного пароля.

## Чек-лист защиты

1. **Лимит попыток** на аккаунт и на IP: 5–10 ошибок → пауза с ростом или блокировка.
2. **Задержка ответа** 200–500 мс — превращает 1000 попыток/с в 2–5.
3. **Пароли — только хешами**: `argon2id` (лучше), `bcrypt`, `scrypt`; не md5/sha1.
4. **Одинаковый ответ и время** для «нет пользователя» и «неверный пароль».
5. **2FA**: украденный пароль перестаёт давать доступ сам по себе.
6. **Логи и алерты** на всплеск ошибок входа.
7. Админку не выставлять в интернет без нужды: `127.0.0.1`, VPN, SSH-туннель.

В `target_demo.py` защита — это `RESPONSE_DELAY`, `MAX_FAILS`, `LOCK_SECONDS`.
